How this works

One chunk in flight, each waiting for its own ack — the device takes MQTT payloads with a zero timeout, so a chunk arriving during a flash write is dropped silently. A nack names the sequence the device wants and the transfer rewinds to it.

An unanswered chunk is resent, not fatal. The device holds its session for 60 s, so it is still there to answer; and because a resend of a chunk it already has comes back as a nack naming what it does want, one mechanism covers a lost chunk and a lost ack alike. Timeout × resends stays inside that 60 s. Blind is for a sleeping leaf: it holds no route and cannot acquire one inside an 85 ms wake, so its first replies go nowhere; the gateway parks the offer and sends it on the next wake.

The chip-id check that matters is in the device, on the first chunk — a check here would only protect this page.

Join window let in devices that have only the factory key

A device flashed from the repository has only the factory key from mesh_key.h. Once the mesh has rotated its key, that key opens nothing, except while a window is open: then the mesh answers the device with the current channel and key. Power the new device on while the window is open. A mains node joins within seconds, and a sleeper on its next wake. Also use a window for a device shown as stranded below.

Backup what a gateway needs if it loses its own record

Since the first key rotation, the mesh key exists only in the devices. A gateway whose flash is erased comes back on the factory key, and every node ignores it. Restoring the newest backup puts it back. The add-on keeps one automatically after every change. The file holds the mesh key, so keep it like a password. A restore is only accepted while the gateway is on the factory record.
